# 採購訊號契約

本文件定義 dashboard 的 **市場趨勢參考訊號**。訊號只使用公開市場行情的數學衍生值，不使用供應商報價、庫存、交期、稅費、物流、合約、公司採購量、SAP 或內部決策門檻。因此所有訊號都是供人員進一步查證的參考，不是「買／不買」、停買、議價承諾或確認採購建議。

## 即時看板訊號

即時 row 的 `changePercent` 是百分比點，例如 2% 會表示為數字 `2`。在資料狀態為 `OK` 時，既有前端 heuristic 使用以下門檻：

| 條件 | 顯示訊號 | 意義 |
| --- | --- | --- |
| `changePercent >= 2` | `成本上升參考` | 近期公開行情上漲，建議核對供應商有效報價。 |
| `changePercent <= -2` | `可議價參考` | 近期公開行情下跌，僅代表可帶入議價查證。 |
| 其餘有限值 | `穩定` | 未跨越上述短期門檻，不表示價格或供應穩定。 |
| `FALLBACK`、`STALE`、`API_ERROR` 或 `NO_DATA` | 備援／快取／錯誤狀態 | 資料狀態優先，不能把非即時資料包裝成即時訊號。 |

介面會把上述短期訊號與資料狀態分開呈現。`FALLBACK` 表示公開備援成功，不代表資料品質等於 primary；`STALE` 表示最後一次成功的真實資料，不代表當下行情。

## 歷史決策參考

`/api/history` 與 Excel 的歷史訊號由 `buildDecision` 產生。輸入是有效歷史 close rows、最新值、期間 high／low、最新 row 的歷史 change ratio，以及資料是否低於該期間的最低資料充足度。位置公式為：

```text
position = (current - low) / (high - low)
```

若 `high === low`，position 設為 `0.5`；若沒有任何有效 close，訊號是 `建議觀望` 且會明確說明資料不足。條件依程式順序套用，前面條件優先於後面條件：

| 優先序 | 條件 | 訊號 | 預設參考動作 |
| ---: | --- | --- | --- |
| 1 | `position >= 0.85` 或 `latestChange >= 0.05` | `高風險` | 暫緩追價，先確認合約價與替代料。 |
| 2 | `position >= 0.70` 或 `latestChange >= 0.02` | `成本上升` | 確認供應商報價有效期，避免一次性大量買高。 |
| 3 | `latestChange <= -0.04` | `成本下降` | 追蹤供應商是否同步反映行情下跌。 |
| 4 | `position <= 0.30` 或 `latestChange <= -0.02` | `可議價` | 要求供應商依行情下修報價。 |
| 5 | `(high - low) / abs(current) > 0.25` 且 current 不為 0 | `建議分批採購` | 分批下單，降低短期波動風險。 |
| 6 | 其他有效資料 | `穩定` | 維持正常採購節奏。 |

這些參考動作是產品原有的文字提示，並已在 UI 與匯出中附加 `市場趨勢參考，非採購指示`。若資料不足但仍有 rows，系統會在 risk 欄位加上「歷史資料不足，趨勢判斷需保守」；若沒有有效 rows，則要求等待公開資料恢復。

## 可重現性與測試

離線測試以固定 close rows 驗證高風險、成本上升、成本下降、可議價、建議分批採購與穩定等門檻，也驗證 insufficient history、nearest-prior FX 與 period row/span 規則。未經客觀缺陷證據，不應為了讓某次 live smoke 結果更好看而改動這些門檻。

## 不在本契約內的資料

供應商現貨價、公司議價空間、MOQ、交期、付款條件、庫存、替代料認證、含稅含運成本、合約敞口、採購核決層級與公司風險偏好都不是目前訊號的輸入。需要這些輸入時，必須另行建立 private、受權限保護且可稽核的業務資料契約。
